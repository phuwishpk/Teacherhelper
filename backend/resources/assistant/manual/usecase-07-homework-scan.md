# การบ้านแบบใบงานของแอปและการสแกน

การบ้านแบบ **ใบงานของแอป** ครูสร้างคำถามในระบบ แล้วพิมพ์ใบงานรายคนที่มีชื่อ QR และกรอบคำตอบ เมื่อนักเรียนทำเสร็จ ครูสแกนด้วยแอป Android ระบบรู้จาก QR ว่าเป็นงานของใคร หน้าใด แล้วตัดภาพคำตอบรายข้อส่งไปตรวจ ทุก use case ในบทนี้ทำได้โดยครูผู้สอนรายวิชาของการบ้าน (ครูประจำชั้นหรือครูร่วมสอน) ครูประจำชั้นดูการบ้านของครูร่วมสอนได้อย่างเดียว การสแกน คิวอัปโหลด และการเตรียมสแกนออฟไลน์มีเฉพาะในแอป Android

## สร้างการบ้านแบบใบงานของแอป

```uc
ผู้ใช้หลัก: ครู
เป้าหมาย: สร้างการบ้านที่จะพิมพ์เป็นใบงานของแอปแล้วสแกนตรวจ
เงื่อนไขก่อนเริ่ม: มีห้องเรียน (UC-T10) และรายวิชาที่ผูกกับห้องนั้น (UC-T22)
ผลลัพธ์: การบ้านสถานะ **ร่าง** อยู่ในแท็บ **การบ้าน** พร้อมให้เพิ่มคำถาม นักเรียนยังไม่เห็นจนกว่าการบ้านจะ **พร้อมใช้** (UC-T30)
ใช้ได้บน: เว็บ, Android
```

**ขั้นตอนการใช้งาน**

1. เปิดแท็บ **การบ้าน** แล้วกด **สร้างการบ้าน** (หรือกด **สร้างการบ้าน** ที่หน้าห้องเรียน)
2. กรอก **ชื่อการบ้าน** และ **คำชี้แจงถึงนักเรียน (ไม่บังคับ)** ไม่เกิน 2,000 ตัวอักษร นักเรียนเห็นข้อความนี้ในหน้าส่งงาน
3. เลือก **ห้องเรียน** แล้วเลือก **รายวิชา** ของห้องนั้น เลือก **แผนการสอน (ไม่บังคับ)** **หัวข้อ** และ **หมวดคะแนน** ได้
4. แนบ **ไฟล์และลิงก์** ได้ด้วย **แนบไฟล์** หรือ **แนบลิงก์** และเลือก **ส่งถึง** **ทั้งห้อง** หรือ **เลือกนักเรียน**
5. ที่ **รูปแบบการบ้าน** เลือก **ใบงานของแอป** แล้วตั้งค่าที่เหลือตามตาราง
6. กด **สร้างการบ้าน** ระบบแสดง **สร้างการบ้านแล้ว เพิ่มคำถามได้เลย** และเปิดหน้าการบ้าน (UC-T28)

| ช่อง | ความหมาย |
|---|---|
| **หัวข้อ** | หน่วยของรายวิชา หรือ **พิมพ์หัวข้อเอง…** (ไม่เกิน 100 ตัวอักษร) |
| **หมวดคะแนน** | หมวดในสมุดคะแนน การบ้านใหม่อยู่ในหมวดตั้งต้นของการบ้าน เปิด **ไม่นับเกรด** ถ้าเป็นงานฝึก |
| **ไฟล์และลิงก์** | PDF รูปภาพ Word Excel PowerPoint ไฟล์ละไม่เกิน 10 MB รวมกับลิงก์ไม่เกิน 5 รายการ |
| **เลือกนักเรียน** | เฉพาะคนที่เลือกเห็นงานและได้ใบงาน คนอื่นเป็น **ไม่ได้รับมอบ** ในสมุดคะแนน |
| **ความเข้มงวดในการตรวจ** | **ผ่อนปรน** **ปกติ** หรือ **เข้มงวด** |
| วันส่ง | แตะ **ไม่กำหนดวันส่ง** เพื่อเลือกวัน ระบบนับถึง 23:59 ของวันนั้น |
| **รับงานส่งช้า** | ปิดไว้ งานที่ส่งหลังกำหนดไม่ถูกตรวจ และนักเรียนส่งในแอปไม่ได้ |
| **เฉพาะคะแนน** | นักเรียนเห็นคะแนนกับข้อความสำเร็จรูป AI ไม่เขียนคำอธิบาย ประหยัดค่าใช้จ่าย |

**กรณีอื่น**

- **3ก** ห้องยังไม่มีรายวิชา: ฟอร์มแจ้ง **ห้องนี้ยังไม่มีรายวิชา สร้างรายวิชาและผูกกับห้องนี้ก่อน** กด **สร้างรายวิชา** (UC-T22) แล้วระบบเลือกรายวิชาใหม่ให้
- **3ข** รายวิชายังไม่ได้ตั้งสมุดคะแนน: ช่องหมวดแสดง **รายวิชานี้ยังไม่ได้ตั้งค่าสมุดคะแนน ตั้งค่าได้ที่หน้ารายวิชา > สมุดคะแนน** (UC-T59)
- **4ก** ห้องผูกกับ Google Classroom ของครู: มีช่องติ๊ก **ส่งไป Google Classroom ด้วย** (ติ๊กไว้ตั้งต้น) ระบบโพสต์เป็นงานในคอร์สทันทีที่การบ้านพร้อมใช้ (UC-T76)
- **6ก** ยังไม่เลือกห้องหรือรายวิชา: ระบบแจ้ง **เลือกห้องเรียนและรายวิชา**

## เพิ่มและแก้คำถาม

```uc
ผู้ใช้หลัก: ครู
เป้าหมาย: ใส่โจทย์ คะแนนเต็ม เฉลย และตัวชี้วัดของแต่ละข้อ
เงื่อนไขก่อนเริ่ม: มีการบ้านแล้ว (UC-T27 หรือ UC-T36)
ผลลัพธ์: ข้อใหม่อยู่ในรายการ **คำถาม** ของหน้าการบ้าน ข้อแสดงวิธีทำและอัตนัยมีป้าย **rubric: ร่างแล้ว รออนุมัติ**
ใช้ได้บน: เว็บ, Android
```

**ขั้นตอนการใช้งาน**

1. ที่หน้าการบ้าน กด **เพิ่มคำถาม** มุมล่าง
2. เลือก **ประเภทคำถาม** พิมพ์ **โจทย์** ตามที่จะปรากฏบนใบงาน (ข้อปรนัยพิมพ์ตัวเลือกไว้ในโจทย์) และ **คะแนนเต็ม** (ไม่เกิน 100)
3. ข้อแสดงวิธีทำและอัตนัย ใส่ **จำนวนบรรทัดคำตอบ** (ไม่เกิน 15 บรรทัด)
4. กรอกเฉลยตามประเภทในตาราง
5. ที่ **ตัวชี้วัด / ทักษะ** กด **เลือกทักษะ** (ไม่เกิน 10 ตัวต่อข้อ)
6. กด **เพิ่มข้อ** ระบบแสดง **บันทึกข้อแล้ว**
7. แก้ข้อโดยแตะข้อในรายการ แล้วกด **บันทึก** ลบด้วยไอคอนถังขยะ **ลบข้อ** ท้ายข้อ

| ประเภท | นักเรียนตอบ | เฉลยที่ครูกรอก |
|---|---|---|
| **ปรนัย** | ฝนวงกลม A–D บนใบงาน | เลือกข้อที่ถูก A B C หรือ D |
| **เติมคำตอบสั้น** | เขียนในกรอบ | **คำตอบที่ยอมรับ (บรรทัดละคำตอบ)** และ **การเทียบคำตอบ** แบบ **ยืดหยุ่น** หรือ **ตรงตัว (สะกดคำ)** |
| **แสดงวิธีทำ** | วิธีทำทีละบรรทัด และคำตอบสุดท้ายในกรอบ | **คำตอบสุดท้ายที่ยอมรับ (บรรทัดละคำตอบ)** และ **ขั้นตอนอ้างอิง (บรรทัดละขั้น)** |
| **อัตนัย** | เขียนตอบเป็นข้อความ | ไม่มีเฉลยตายตัว ตรวจตาม rubric (UC-T29) ใส่ **คำตอบตัวอย่างของครู (ไม่บังคับ)** ได้ |

**กรณีอื่น**

- **4ก** คำตอบเป็นตัวเลข (เติมคำตอบสั้นและแสดงวิธีทำ): เปิด **คำตอบเป็นตัวเลข** แล้วกรอก **ค่าตัวเลข** และ **คลาดเคลื่อนได้ ±** ตัวอ่านตัวเลขในเครื่องช่วยตรวจซ้ำ
- **4ข** การบ้านแบบไม่ใช้ใบงานของแอป: เว้นเฉลยว่างไว้ได้ ถ้าจะให้ AI อ่านหรือร่างทีหลัง แต่ต้องครบก่อนอนุมัติเฉลย (UC-T37)
- **6ก** กรอกไม่ครบหรือเกินกำหนด: ระบบแจ้ง เช่น **กรอกโจทย์** **เลือกข้อที่ถูก** **กรอกคำตอบที่ยอมรับอย่างน้อย 1 แบบ** หรือ **การบ้านหนึ่งชุดมีได้ไม่เกิน 100 ข้อ**
- **7ก** เพิ่ม ลบ หรือแก้โจทย์ คะแนน ประเภท หรือจำนวนบรรทัดหลังสร้าง layout: การบ้านกลับเป็น **ร่าง** ต้องสร้าง layout ใหม่ก่อนพิมพ์อีกครั้ง (UC-T30)
- **7ข** ข้อที่มีคำตอบของนักเรียนแล้วลบไม่ได้: **ข้อนี้มีคำตอบของนักเรียนที่สแกนแล้ว ลบไม่ได้**

## ร่างและอนุมัติ rubric

```uc
ผู้ใช้หลัก: ครู
ผู้ใช้รอง: Gemini
เป้าหมาย: กำหนดเกณฑ์ที่ AI ใช้ให้คะแนนข้อแสดงวิธีทำและข้ออัตนัย
เงื่อนไขก่อนเริ่ม: มีข้อแสดงวิธีทำหรืออัตนัย (UC-T28) ถ้าจะให้ AI ร่าง ต้องใส่ Gemini API key แล้ว (UC-T05)
ผลลัพธ์: rubric ของข้อเป็น **อนุมัติแล้ว** เมื่ออนุมัติครบทุกข้อ จึงสร้าง layout ได้ (UC-T30)
ใช้ได้บน: เว็บ, Android
```

**ขั้นตอนการใช้งาน**

1. ที่หน้าการบ้าน แตะป้าย **rubric: ร่างแล้ว รออนุมัติ** ท้ายข้อ (หรือกด **Rubric** มุมขวาบนของหน้าแก้ข้อ)
2. กด **ให้ AI ร่าง rubric** (ข้ออัตนัย) หรือ **ให้ AI ร่างขั้นตอนอ้างอิง** (ข้อแสดงวิธีทำ) แล้วรอจนระบบแจ้งว่าร่างแล้ว
3. ข้อแสดงวิธีทำ: แก้ **ขั้นตอนอ้างอิง (บรรทัดละขั้น)** ให้ถูก ข้อนี้ตรวจจากวิธีทำทีละบรรทัดกับคำตอบสุดท้ายตามเฉลย ไม่มีเกณฑ์แยกข้อ
4. ข้ออัตนัย: แก้ **เกณฑ์** และ **คะแนน** ของแต่ละข้อ กด **เพิ่มเกณฑ์** หรือกากบาทเพื่อลบ แล้วติ๊ก **เกณฑ์หลัก (แก่นของคำตอบ)** หนึ่งข้อ
5. กด **บันทึกและอนุมัติ** ระบบแสดง **อนุมัติ rubric แล้ว** (ข้อแสดงวิธีทำ: **อนุมัติขั้นตอนอ้างอิงแล้ว**)

**กรณีอื่น**

- **2ก** ไม่มี key: ระบบแจ้ง **ยังไม่มี Gemini API key ให้ใช้ ใส่ key ที่หน้าตั้งค่าก่อนแล้วลองอีกครั้ง** เขียนเกณฑ์เองด้วย **เพิ่มเกณฑ์** ได้
- **2ข** รอเกิน 3 นาที: **ยังไม่ได้ร่างจาก AI (คิวอาจยังไม่ทำงาน) ลองกดใหม่ภายหลัง**
- **5ก** ข้ออัตนัยต้องมีเกณฑ์ 1–10 ข้อที่มีทั้งคำอธิบายและคะแนน (**เกณฑ์ข้อ N ต้องมีคำอธิบายและคะแนน**) มีเกณฑ์หลักหนึ่งข้อพอดี และคะแนนรวมเท่าคะแนนเต็ม ไม่อย่างนั้นแอปไม่อนุมัติและแจ้ง **เลือกเกณฑ์หลัก (แก่นของคำตอบ) 1 ข้อก่อนอนุมัติ** หรือ **คะแนนรวมของเกณฑ์ (X) ต้องเท่ากับคะแนนเต็มของข้อ (Y)** แก้ให้ครบแล้วกด **อนุมัติ** อีกครั้ง
- **5ข** ข้อแสดงวิธีทำที่ไม่มีขั้นตอนอ้างอิง: ระบบถาม **ยังไม่มีขั้นตอนอ้างอิง** กด **อนุมัติ** เพื่อผ่านได้

**ถ้าแก้คะแนนเต็มของข้อ หรือให้ AI ร่างใหม่ rubric ของข้อนั้นกลับเป็น **ร่างแล้ว รออนุมัติ** และการบ้านที่สร้าง layout แล้วกลับเป็น **ร่าง** ต้องอนุมัติและสร้าง layout อีกครั้ง**

## สร้าง layout และพิมพ์ใบงาน

```uc
ผู้ใช้หลัก: ครู
เป้าหมาย: จัดหน้าใบงานแล้วได้ไฟล์ PDF ใบงานรายคนไปพิมพ์แจก
เงื่อนไขก่อนเริ่ม: การบ้านแบบใบงานของแอปมีคำถามแล้ว (UC-T28) rubric ของข้อแสดงวิธีทำและอัตนัยอนุมัติครบ (UC-T29) และห้องมีนักเรียน
ผลลัพธ์: การบ้านเป็น **พร้อมใช้** เฉลยถือว่าอนุมัติแล้ว นักเรียนเห็นการบ้าน และครูได้ PDF ที่มีใบงานของนักเรียนทุกคน (หรือเฉพาะคนที่เลือก)
ใช้ได้บน: เว็บ, Android
```

**ขั้นตอนการใช้งาน**

1. ที่การ์ด **ใบงาน** ของหน้าการบ้าน กด **สร้าง layout** (ถ้ามี layout แล้ว ปุ่มเป็น **สร้าง layout ใหม่**)
2. ระบบแสดง **สร้าง layout เวอร์ชัน N แล้ว (P หน้า) พิมพ์ใบงานได้เลย** และการบ้านเปลี่ยนเป็น **พร้อมใช้** ถ้าติ๊ก **ส่งไป Google Classroom ด้วย** ไว้ ระบบโพสต์งานในคอร์สด้วย (UC-T76)
3. กด **พิมพ์ใบงาน** รอข้อความเปลี่ยนจาก **อยู่ในคิว** เป็น **กำลังสร้าง PDF** และ **กำลังดาวน์โหลด…**
4. เลือก **เปิดไฟล์** **บันทึกลงเครื่อง** หรือ **แชร์ / ส่งไปพิมพ์** (บนเว็บไม่มี **เปิดไฟล์** และใช้ **ดาวน์โหลด** แทน **บันทึกลงเครื่อง**)
5. พิมพ์ลงกระดาษ A4 ขนาดจริง (ไม่ย่อ ไม่ขยาย) แล้วแจกให้ตรงชื่อ

**กรณีอื่น**

- **1ก** ปุ่มกดไม่ได้: การ์ดแจ้ง **เพิ่มคำถามก่อน จึงจะสร้าง layout ได้** หรือ **มี N ข้อ (แสดงวิธีทำ/อัตนัย) ที่ยังไม่อนุมัติ rubric ต้องอนุมัติให้ครบก่อนสร้าง layout**
- **1ข** ข้อยาวเกินหน้า: **ข้อ N ยาวเกินหนึ่งหน้า ลดจำนวนบรรทัดคำตอบหรือทำโจทย์ให้สั้นลง**
- **3ก** แก้คำถามหลังสร้าง layout: ต้องสร้าง layout ใหม่ก่อน (**ต้องสร้าง layout ให้เป็นปัจจุบันก่อนพิมพ์ใบงาน**) ใบงานที่พิมพ์ไปแล้วยังสแกนได้ตาม layout เดิม
- **3ข** ห้องยังไม่มีนักเรียน: ระบบแจ้ง **ห้องนี้ยังไม่มีนักเรียน**
- **3ค** รอเกิน 5 นาที: **สร้าง PDF ใช้เวลานานเกินไป ลองดูสถานะใหม่ภายหลัง** ให้กดพิมพ์อีกครั้งภายหลัง

**ใบงานเป็นของรายคน ห้ามถ่ายเอกสารแจก**
QR บนแต่ละแผ่นระบุตัวนักเรียน ถ้าถ่ายเอกสารแผ่นเดียวแจกหลายคน งานทุกแผ่นจะถูกบันทึกเป็นของนักเรียนคนเดียว ให้นักเรียนเขียนคำตอบในกรอบเท่านั้น และห้ามพับหรือขีดเขียนทับสัญลักษณ์สี่เหลี่ยมที่มุมทั้ง 4

## จับคู่ข้อกับตัวชี้วัด

```uc
ผู้ใช้หลัก: ครู
ผู้ใช้รอง: Gemini
เป้าหมาย: ผูกทุกข้อของการบ้านกับตัวชี้วัด เพื่อให้คะแนนคิดเป็นระดับความเข้าใจของนักเรียน
เงื่อนไขก่อนเริ่ม: การบ้านมีคำถามแล้ว (UC-T28) ถ้าจะให้ AI เสนอ ต้องผูกการบ้านกับแผนการสอนที่มีตัวชี้วัด (UC-T25) และใส่ Gemini API key แล้ว (UC-T05)
ผลลัพธ์: แต่ละข้อมีตัวชี้วัด และคะแนนของข้อนับในกราฟและตารางทักษะ (UC-T66)
ใช้ได้บน: เว็บ, Android
```

**ขั้นตอนการใช้งาน**

1. ที่หน้าการบ้าน กดการ์ด **จับคู่ข้อกับตัวชี้วัด** ระบบเปิดหน้า **จับคู่ตัวชี้วัด**
2. กด **ให้ AI เสนอตัวชี้วัด** ใส่ **คำแนะนำถึง AI (ไม่บังคับ)** แล้วกด **ส่งให้ AI** (AI เลือกได้เฉพาะตัวชี้วัดของแผนนั้น)
3. รอข้อความ **AI กำลังเสนอตัวชี้วัด อาจใช้เวลาหนึ่งถึงสองนาที** จนขึ้นว่า **AI เสนอตัวชี้วัดให้ N ข้อ**
4. ในแต่ละข้อ กด **ใช้** ที่ข้อเสนอที่ถูกต้อง หรือกด **ใช้ข้อเสนอทั้งหมด** หรือ **เลือกตัวชี้วัดเอง** เอาตัวที่ไม่ต้องการออกด้วยกากบาทบนชิป
5. กด **บันทึก** มุมขวาบน ระบบแสดง **บันทึกตัวชี้วัดแล้ว N ข้อ**

**กรณีอื่น**

- **2ก** การบ้านไม่ผูกแผน: ไม่มีปุ่มให้ AI เสนอ หน้าแนะนำให้เลือกตัวชี้วัดเองทีละข้อ หรือเลือกแผนการสอนที่หน้าแก้ไขการบ้าน (UC-T32) แผนที่ไม่มีตัวชี้วัดขึ้น **แผนนี้ยังไม่มีตัวชี้วัด เพิ่มตัวชี้วัดของแผนที่หน้ารายวิชาก่อน จึงให้ AI เสนอได้**
- **2ข** ไม่มี key: **ยังไม่ได้ใส่ Gemini API key ใส่ได้ที่หน้าตั้งค่า แล้วลองอีกครั้ง** พร้อมปุ่ม **ไปใส่ key**
- **5ก** ออกจากหน้าโดยยังไม่บันทึก: ระบบถาม **ทิ้งการแก้ไข?**
- **ทุกขั้น** ข้อที่ยังไม่ผูกมีคำเตือน **มี N ข้อยังไม่ผูกตัวชี้วัด คะแนนข้อเหล่านี้จะไม่นับในกราฟ** แต่ไม่ห้ามพิมพ์หรือตรวจ เลือกตัวชี้วัดตอนเพิ่มคำถามก็ได้ (UC-T28) และเมื่อกด **อนุมัติเฉลย** ที่หน้าเฉลย ระบบให้ AI เสนอให้เองหนึ่งครั้ง ถ้าแผนมีตัวชี้วัด ยังมีข้อที่ไม่ผูก และมี Gemini API key

## แก้ไขหรือลบการบ้าน

```uc
ผู้ใช้หลัก: ครู
เป้าหมาย: เปลี่ยนการตั้งค่าของการบ้าน หรือลบการบ้านที่ยังไม่ได้ใช้
เงื่อนไขก่อนเริ่ม: มีการบ้านในรายวิชาของครูเอง (UC-T27 หรือ UC-T36)
ผลลัพธ์: การบ้านใช้ค่าใหม่ หรือถูกลบพร้อมคำถามทั้งหมด
ใช้ได้บน: เว็บ, Android
```

**ขั้นตอนการใช้งาน**

1. ที่หน้าการบ้าน กดไอคอนดินสอ **แก้ไข** มุมขวาบน ระบบเปิดหน้า **แก้ไขการบ้าน**
2. แก้ช่องที่ต้องการ เช่น ชื่อ คำชี้แจง รายวิชา แผน หัวข้อ ไฟล์ ผู้รับ ความเข้มงวด หรือวันส่ง (ล้างวันส่งด้วยปุ่ม **ล้างวันส่ง**) ห้องเรียนเปลี่ยนไม่ได้
3. กด **บันทึก** ระบบแสดง **บันทึกแล้ว**
4. ลบ: ขณะการบ้านเป็น **ร่าง** กดไอคอนถังขยะ **ลบ** ระบบถาม **ลบการบ้าน "…"?** พร้อมข้อความ **ลบได้เฉพาะการบ้านที่ยังเป็นร่าง คำถามทั้งหมดจะถูกลบด้วย**
5. กด **ลบ** ระบบแสดง **ลบการบ้านแล้ว**

**กรณีอื่น**

- **2ก** **รูปแบบการบ้าน** เปลี่ยนได้เฉพาะฉบับร่างที่ยังไม่เคยสร้าง layout และยังไม่มีงานส่ง ไม่เช่นนั้นฟอร์มแจ้ง **เปลี่ยนรูปแบบไม่ได้หลังสร้าง layout หรือมีงานส่งแล้ว**
- **2ข** การบ้านที่โพสต์ลง Google Classroom แล้ว: เปลี่ยนผู้รับไม่ได้ (**โพสต์ลง Google Classroom แล้ว เปลี่ยนผู้รับไม่ได้**) และแก้ไฟล์แนบไม่ได้
- **5ก** ร่างที่พิมพ์ใบงานไปแล้วหรือโพสต์ลง Classroom แล้วลบไม่ได้: ระบบแจ้ง **การบ้านนี้พิมพ์ใบงานไปแล้ว ลบไม่ได้** หรือ **การบ้านนี้โพสต์ลง Google Classroom แล้ว ลบไม่ได้**
- **ทุกขั้น** การบ้านของครูร่วมสอนในห้องของครูประจำชั้นมีแถบ **งานของครูประจำวิชา อ่านอย่างเดียว** และไม่มีปุ่มแก้ไขหรือลบ

## สแกนใบงานด้วยมือถือ

```uc
ผู้ใช้หลัก: ครู
เป้าหมาย: ถ่ายใบงานที่นักเรียนทำแล้วทีละแผ่น ให้ระบบตัดภาพคำตอบรายข้อและส่งไปตรวจ
เงื่อนไขก่อนเริ่ม: แจกใบงานที่พิมพ์จากระบบแล้ว (UC-T30) ใช้แอป Android ที่เข้าสู่ระบบด้วยบัญชีครูเจ้าของการบ้าน และอนุญาตให้แอปใช้กล้อง
ผลลัพธ์: หน้าที่ยืนยันแล้วเข้าคิวอัปโหลดและถูกส่งขึ้นเซิร์ฟเวอร์ ระบบตรวจ (UC-X01) แล้วผลรอในแท็บ **ตรวจทาน** (UC-T40)
ใช้ได้บน: Android
เรียกใช้: X01
```

**ขั้นตอนการใช้งาน**

1. ที่หน้าหลัก กดปุ่ม **สแกนใบงาน** ไม่ต้องเลือกการบ้านหรือนักเรียนก่อน เพราะ QR บนใบงานบอกทั้งหมด
2. วางใบงานบนพื้นเรียบ ให้เห็นสัญลักษณ์สี่เหลี่ยมครบทั้ง 4 มุม แล้วกดปุ่มถ่ายรูปวงกลม (ที่มืดกด **เปิดไฟฉาย**) ระบบขึ้น **กำลังถ่ายภาพ…** และ **กำลังตรวจใบงาน…**
3. ที่หน้ายืนยัน ตรวจชื่อ เลขที่ และหน้า กับภาพย่อของแต่ละกรอบ ใต้ภาพบอก **มีคำตอบ** **ว่าง** **ไม่ได้ฝน** หรือ **ฝน** ตามด้วยตัวเลือก
4. ถ้าภาพครบและอ่านออก กด **ยืนยัน แล้วสแกนต่อ** ระบบขึ้น **บันทึก … หน้า P แล้ว สแกนแผ่นต่อไปได้เลย** ถ้าภาพไม่ดีกด **ถ่ายใหม่**
5. ทำซ้ำจนครบทุกแผ่น หัวหน้าจอบอก **สแกนใบงาน · บันทึกแล้ว N หน้า** ภาพถูกส่งเองเมื่อมีอินเทอร์เน็ต (UC-T34)

**กรณีอื่น**

- **1ก** ใช้รูปที่ถ่ายไว้แล้ว: กดไอคอน **เลือกไฟล์** รูปที่ใช้ได้ผ่านหน้ายืนยันแบบเดียวกัน (กด **ยืนยัน** หรือ **ข้ามไฟล์นี้**) รูปที่ใช้ไม่ได้และ PDF ทุกไฟล์ไปรวมที่หน้า **ไม่พบสัญลักษณ์หรือ QR ใน N ไฟล์** เลือกไฟล์ของนักเรียนคนเดียวกันไม่เกิน 5 ไฟล์ แล้วกด **ส่งแบบรูปทั้งหน้า** (UC-T39)
- **2ก** ภาพใช้ไม่ได้: หน้าขึ้น **ถ่ายใหม่อีกครั้ง** พร้อมเหตุผล เช่น **อ่าน QR ที่หัวกระดาษไม่ได้ ระวังเงาหรือแสงสะท้อนบน QR แล้วถ่ายใหม่** ถ้าเหตุผลมีเพียง **ภาพไม่คมชัด ถือโทรศัพท์ให้นิ่งและรอให้กล้องโฟกัสก่อนถ่าย** และครูดูแล้วอ่านออก กด **ใช้ภาพนี้ต่อ** ได้
- **2ข** หยิบผิดแผ่น: **QR นี้ไม่ใช่ใบงานของ Krucheck** หรือ **ไม่พบการบ้าน #N ในบัญชีนี้ (อาจเป็นใบงานของครูคนอื่น)**
- **2ค** ไม่มีอินเทอร์เน็ตและเครื่องยังไม่มี layout ของใบงาน: **ยังไม่มี layout ของใบงานนี้ในเครื่อง** กด **เก็บไว้ในคิว** (UC-T35)
- **3ก** สแกนแผ่นเดิมซ้ำขณะภาพแรกยังรอในคิว: **หน้านี้สแกนไว้แล้วและยังรออยู่ในคิว ถ้ายืนยัน ระบบจะใช้ภาพล่าสุดแทน**

**บนเว็บ หน้าสแกนแสดง **สแกนใบงานได้เฉพาะในแอป Android** พร้อมปุ่ม **อัปโหลดรูปเพื่อตรวจ** ให้ส่งรูปหรือ PDF ของงานแทน (UC-T39)**

## จัดการคิวอัปโหลด

```uc
ผู้ใช้หลัก: ครู
เป้าหมาย: ดูว่าภาพสแกนในเครื่องส่งขึ้นเซิร์ฟเวอร์แล้วหรือยัง และจัดการรายการที่ค้างหรือถูกปฏิเสธ
เงื่อนไขก่อนเริ่ม: มีภาพสแกนในเครื่อง (UC-T33 หรือ UC-T55)
ผลลัพธ์: ภาพที่ค้างถูกส่ง ส่งซ้ำ ยืนยันแทนที่ หรือลบออกจากเครื่อง ภาพที่ส่งสำเร็จถูกลบจากเครื่อง
ใช้ได้บน: Android
```

**ขั้นตอนการใช้งาน**

1. กดไอคอนรูปเมฆ **คิวอัปโหลด** บนแถบด้านบน (หน้าหลักหรือหน้าสแกน) ตัวเลขบนไอคอนคือจำนวนรายการที่ยังส่งไม่เสร็จ
2. ดูสถานะของแต่ละรายการตามตาราง รายการที่มีปัญหามีเหตุผลเป็นตัวอักษรสีแดง
3. กด **อัปโหลดตอนนี้** เพื่อส่งทั้งคิวทันที ระบบสรุป เช่น **ส่งแล้ว N รายการ**
4. ที่รายการ กดปุ่มตามสถานะ: **ลองใหม่** **ประมวลผลต่อ** **ยืนยันแทนที่** หรือ **ลบ**
5. กดไอคอนไม้กวาด **ลบรายการที่ส่งแล้ว** เพื่อล้างรายการที่ส่งสำเร็จออกจากรายการ

| สถานะ | ความหมาย | ปุ่มที่ใช้ได้ |
|---|---|---|
| **รออัปโหลด** | รอส่ง หรือรอลองใหม่ | **ลองใหม่** **ลบ** |
| **กำลังอัปโหลด** | กำลังส่ง ถ้าค้างเกิน 10 นาทีจะมี **ลองใหม่** และ **ลบ** | – |
| **ส่งแล้ว** | เซิร์ฟเวอร์รับแล้ว | **ลบ** |
| **รอ layout** | สแกนตอนไม่มีเน็ตและเครื่องยังไม่มี layout | **ประมวลผลต่อ** **ลบ** |
| **รอครูยืนยัน** | ผลของนักเรียนคนนี้เผยแพร่แล้ว | **ยืนยันแทนที่** **ลบ** |
| **ถูกปฏิเสธ** | เซิร์ฟเวอร์ไม่รับ มีเหตุผลกำกับ | **ลองใหม่** **ลบ** |

**กรณีอื่น**

- **4ก** **ลบ** ภาพที่ยังไม่ส่ง: ระบบถาม **ลบสแกนนี้?** และเตือนว่า **ภาพที่สแกนไว้จะถูกลบและไม่ถูกส่งขึ้นเซิร์ฟเวอร์**
- **4ข** รายการ **ถูกปฏิเสธ**: อ่านเหตุผลในรายการก่อนกด **ลองใหม่** เช่น ครูประจำชั้นสแกนใบงานของครูร่วมสอน ได้เหตุผล **เฉพาะครูผู้สอนรายวิชานี้ที่ทำได้ ครูประจำชั้นดูได้อย่างเดียว** ให้ลบ แล้วให้ครูเจ้าของการบ้านสแกนเอง
- **ทุกขั้น** ระบบส่งเองเบื้องหลังเมื่อมีเครือข่าย ถ้าส่งไม่ได้จะลองใหม่โดยเว้นช่วงนานขึ้นเรื่อยๆ ตั้งแต่ 30 วินาทีจนสูงสุด 1 ชั่วโมง
- **ทุกขั้น** ออกจากระบบขณะยังมีภาพค้าง: ระบบเตือน **ยังมีสแกนที่ยังไม่ได้ส่ง N รายการ** ถ้ากด **ลบและออกจากระบบ** ภาพเหล่านั้นถูกลบและไม่ถูกส่ง

**บนเว็บไม่มีคิวอัปโหลด ถ้าเปิดหน้านี้จะเห็น **คิวอัปโหลดมีเฉพาะในแอป Android** เพราะรูปหรือ PDF ที่อัปโหลดบนเว็บส่งถึงเซิร์ฟเวอร์ทันที**

## เตรียมสแกนออฟไลน์

```uc
ผู้ใช้หลัก: ครู
เป้าหมาย: เก็บรายชื่อนักเรียนและ layout ของการบ้านไว้ในเครื่อง เพื่อสแกนในห้องที่ไม่มีอินเทอร์เน็ต
เงื่อนไขก่อนเริ่ม: มีอินเทอร์เน็ตขณะเตรียม ห้องยังไม่ปิด และการบ้านของห้องสร้าง layout แล้ว (UC-T30)
ผลลัพธ์: เครื่องมีสำเนารายชื่อและทุกเวอร์ชันของ layout ของการบ้านในห้อง สแกนแล้วตัดภาพและแสดงหน้ายืนยันได้โดยไม่ต้องต่อเน็ต
ใช้ได้บน: Android
```

**ขั้นตอนการใช้งาน**

1. ขณะยังมีอินเทอร์เน็ต เปิดหน้าห้องเรียน แล้วกด **เตรียมสแกนออฟไลน์**
2. รอจากข้อความ **กำลังดาวน์โหลด layout และรายชื่อ…** จนขึ้น **พร้อมสแกนออฟไลน์: นักเรียน N คน, การบ้าน N ชุด, layout N หน้า**
3. ในห้องที่ไม่มีอินเทอร์เน็ต สแกนตามปกติ (UC-T33)
4. ภาพรอในคิวอัปโหลด และถูกส่งเองเมื่อเครื่องต่ออินเทอร์เน็ตได้ (UC-T34)

**กรณีอื่น**

- **1ก** ข้อมูลที่เตรียมเป็นสำเนา ณ เวลาที่กด และถูกลบเมื่อออกจากระบบ ให้กดใหม่หลังสร้างการบ้านหรือ layout ใหม่ หลังแก้รายชื่อ และหลังเข้าสู่ระบบใหม่
- **3ก** ยังไม่ได้เตรียม หรือใบงานใหม่กว่าที่เตรียมไว้: ระบบแจ้ง **ยังไม่มี layout ของใบงานนี้ในเครื่อง** กด **เก็บไว้ในคิว** (หรือ **ทิ้ง**) ภาพรอในสถานะ **รอ layout** โดยไม่มีหน้ายืนยัน เมื่อกลับมามีเน็ต เปิดหน้าสแกน (ระบบตัดภาพที่รอให้) หรือกด **ประมวลผลต่อ** ในคิวอัปโหลด
- **3ข** นักเรียนไม่อยู่ในรายชื่อที่เตรียมไว้: หน้ายืนยันแสดงรหัสนักเรียนพร้อมข้อความ **ไม่มีในรายชื่อที่เตรียมไว้** ยืนยันได้ตามปกติ เซิร์ฟเวอร์รู้จักนักเรียนจาก QR

**บนเว็บไม่มีปุ่ม **เตรียมสแกนออฟไลน์** ในหน้าห้องเรียน เพราะการสแกนและที่เก็บข้อมูลในเครื่องมีเฉพาะแอป Android**
