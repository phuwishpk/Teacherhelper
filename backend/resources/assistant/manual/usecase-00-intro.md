# เกี่ยวกับเอกสารนี้

เอกสารนี้รวบรวม use case (กรณีการใช้งาน) ทั้งหมดของ Krucheck แต่ละ use case บอกว่าใครเป็นผู้ใช้ ทำเพื่ออะไร ต้องมีอะไรพร้อมก่อน ได้ผลอะไร และทำอย่างไรบนหน้าจอจริงทีละขั้น พร้อมกรณีที่ต่างไปจากปกติ เอกสารจึงใช้ได้ทั้งเป็นเอกสารออกแบบระบบ (use case specification) และเป็นคู่มือการใช้งานที่ค้นตามงานที่ต้องการทำ

ชื่อปุ่ม เมนู และข้อความในขั้นตอนตรงกับที่ระบบแสดงจริง รายละเอียดที่ยาวกว่านี้และภาพหน้าจออยู่ในคู่มือการใช้งานสำหรับครูและนักเรียน ส่วนการติดตั้งและดูแลเซิร์ฟเวอร์อยู่ในคู่มือการติดตั้งระบบ

## Krucheck คืออะไร

Krucheck เป็นระบบช่วยครูตรวจการบ้านและข้อสอบ ครูสร้างงานในระบบ พิมพ์ใบงานหรือกระดาษคำตอบแจกนักเรียน แล้วเก็บงานด้วยการสแกนจากมือถือ อัปโหลดรูป หรือให้นักเรียนส่งรูปเอง AI อ่านลายมือและเสนอคะแนนพร้อมคำอธิบายรายข้อ ข้อสอบแบบฝนตรวจด้วยโปรแกรมโดยไม่ใช้ AI ครูเป็นผู้ตรวจทานและตัดสินทุกครั้ง นักเรียนเห็นผลก็ต่อเมื่อครูเผยแพร่แล้ว

<div class="flow">
<div><b>1 เตรียม</b>ห้องเรียน รายวิชา ตัวชี้วัด การบ้านหรือข้อสอบ</div>
<div><b>2 แจกงาน</b>พิมพ์ใบงาน หรือให้นักเรียนส่งรูปในระบบ</div>
<div><b>3 เก็บงาน</b>สแกนด้วยมือถือ อัปโหลด หรือรับจาก Classroom</div>
<div><b>4 ตรวจทาน</b>AI เสนอคะแนน ครูยืนยันแล้วเผยแพร่</div>
<div><b>5 ติดตาม</b>สมุดคะแนน เกรด ทักษะ และแบบฝึกรายคน</div>
</div>

นอกจากงานตรวจ ระบบยังมีโพสต์ประกาศและเอกสารประกอบของห้อง ตารางสอน การเช็คชื่อรายคาบ การเชื่อมกับ Google Classroom ผู้ช่วย Krucheck ซึ่งเป็นแชทกับ AI สำหรับครู และกล่องการแจ้งเตือนที่อัปเดตทันที ครูแต่ละคนใช้ระบบได้โดยไม่ต้องสังกัดโรงเรียนเดียวกัน นักเรียนมีบัญชีเดียวและเข้าห้องของครูกี่คนก็ได้

## ช่องทางการใช้งาน

| ช่องทาง | ที่อยู่หรือวิธีเปิด | ผู้ใช้ |
|---|---|---|
| **เว็บแอป** | `https://<โดเมน>/app/` บนเบราว์เซอร์ของคอมพิวเตอร์ แท็บเล็ต หรือมือถือ | ครู นักเรียน |
| **แอป Android** | แอปที่ผู้ดูแลระบบแจกให้ติดตั้ง (Android 8.0 ขึ้นไป) | ครู นักเรียน |
| **หน้าผู้ดูแลระบบ** | `https://<โดเมน>/admin` บนเบราว์เซอร์ของคอมพิวเตอร์ | ผู้ดูแลระบบ |
| **นโยบายความเป็นส่วนตัว** | `https://<โดเมน>/privacy` เปิดได้โดยไม่ต้องเข้าสู่ระบบ | ทุกคน |

เว็บแอปและแอป Android ใช้โค้ดและข้อมูลชุดเดียวกัน ต่างกันที่งานซึ่งต้องใช้กล้องและที่เก็บข้อมูลในเครื่อง ได้แก่ การสแกนใบงานและกระดาษคำตอบ คิวอัปโหลด การสแกนแบบไม่มีอินเทอร์เน็ต การถ่ายรูปงานในแอป และการแจ้งเตือนบนเครื่อง ซึ่งมีเฉพาะในแอป Android บนเว็บ หน้าที่เกี่ยวข้องจะแสดงคำอธิบายแทน กล่องการแจ้งเตือน (ปุ่มกระดิ่ง) ใช้ได้ทั้งสองทาง นอกจากนี้มีแอป iOS รุ่นทดสอบที่ทำได้เหมือนแอป Android ยกเว้นการแจ้งเตือนบนเครื่อง ช่อง **ใช้ได้บน** ของแต่ละ use case บอกว่าทำได้ที่ใด

## โครงสร้างของเอกสาร

| ส่วน | เนื้อหา | รหัส use case |
|---|---|---|
| บทที่ 1–3 | เอกสารนี้ ผู้ใช้ระบบ ภาพรวม ลำดับการใช้งานหลัก และรายการ use case ทั้งหมด | - |
| ส่วนที่ 1 ครู | การสมัครและบัญชี ห้องเรียน รายวิชา การบ้าน ข้อสอบ การตรวจทาน สมุดคะแนน การติดตามผล Google Classroom โพสต์ ตารางสอน เช็คชื่อ และผู้ช่วย Krucheck | UC-T01 ถึง UC-T98 |
| ส่วนที่ 2 นักเรียน | การเข้าสู่ระบบและเข้าห้อง การเรียนและส่งงาน ผลการเรียน และบัญชี | UC-S01 ถึง UC-S21 |
| ส่วนที่ 3 ผู้ดูแลระบบ | บัญชีผู้ใช้ และข้อมูลกับบริการของระบบ | UC-A01 ถึง UC-A17 |
| ส่วนที่ 4 งานที่ระบบทำเอง | งานที่ทำงานเบื้องหลังตามคิวหรือตามเวลา เช่น ตรวจด้วย AI และซิงก์กับ Classroom | UC-X01 ถึง UC-X08 |

ทุกบทในส่วนที่ 1–4 เริ่มด้วยแผนภาพ use case ของบทนั้น แล้วตามด้วยรายละเอียดของแต่ละ use case เรียงตามรหัส

## วิธีอ่าน use case หนึ่งรายการ

หัวของแต่ละรายการคือรหัสและชื่อ เช่น <span class="label">UC-T10</span> **สร้างห้องเรียน** อักษรตัวแรกของรหัสบอกส่วนของเอกสาร คือ T ครู, S นักเรียน, A ผู้ดูแลระบบ และ X งานที่ระบบทำเอง ใต้หัวเป็นกล่องข้อมูลดังนี้

| ช่อง | ความหมาย |
|---|---|
| **ผู้ใช้หลัก** | ผู้ที่เริ่มทำ use case นี้เพื่อเป้าหมายของตัวเอง (primary actor) |
| **ผู้ใช้รอง** | ระบบภายนอกที่มีส่วนร่วม เช่น Gemini หรือ Google Classroom (secondary actor) ไม่มีช่องนี้ถ้าไม่มี |
| **เป้าหมาย** | สิ่งที่ผู้ใช้หลักต้องการ |
| **เงื่อนไขก่อนเริ่ม** | สิ่งที่ต้องเป็นจริงก่อนเริ่ม (pre-condition) |
| **ผลลัพธ์** | สิ่งที่เป็นจริงเมื่อทำสำเร็จ (post-condition) |
| **ใช้ได้บน** | เว็บ Android หน้าผู้ดูแลระบบ หรือเซิร์ฟเวอร์ (งานเบื้องหลัง) |
| **เรียกใช้ «include»** | use case อื่นที่เกิดขึ้นทุกครั้งเป็นส่วนหนึ่งของรายการนี้ |
| **ขยายจาก «extend»** | use case หลักที่รายการนี้เพิ่มเข้าไปเมื่อเข้าเงื่อนไข |

ถัดมาคือ **ขั้นตอนการใช้งาน** เป็นลำดับการกระทำของผู้ใช้และการตอบสนองของระบบในกรณีปกติ (main flow) และ **กรณีอื่น** เป็นทางแยกและข้อผิดพลาด (alternative flow) ป้ายหน้าบรรทัดบอกขั้นที่แยกออกไป เช่น **3ก** คือทางแยกแรกของขั้นที่ 3 และ **3ข** คือทางแยกที่สองของขั้นเดียวกัน ส่วน **ทุกขั้น** คือเกิดได้ทุกเมื่อ

ชื่อปุ่ม เมนู แท็บ และข้อความที่ระบบแสดงพิมพ์ด้วย **ตัวหนา** สิ่งที่ผู้ใช้พิมพ์ลงช่องหรือที่อยู่เว็บพิมพ์แบบ `ป.5/1` รหัส use case ในเนื้อหา เช่น UC-T10 กดเพื่อไปยังรายการนั้นได้ในไฟล์ PDF ยกเว้นที่ระบุไว้ ทุก use case ถือว่าผู้ใช้เข้าสู่ระบบแล้ว
